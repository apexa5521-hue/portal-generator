# مولّد صفحات الهبوط الموحدة

لوحة إدارة تُنشئ صفحات تجمع عدة منصات في بطاقات أنيقة، وتُصدَّر كل صفحة برابط واحد قصير: `.../?p=hr`

- **الواجهة:** GitHub Pages (HTML/CSS/JS بدون أدوات بناء)
- **التخزين والإدارة:** Google Sheets + Google Apps Script
- **الملفات:** `index.html` صفحة المستفيد، `admin.html` لوحة الإدارة، `Code.gs` الخادم، `config.js` الإعدادات

> بدون ضبط `API_URL` يعمل النظام بوضع تجريبي يحفظ في متصفحك فقط (للتجربة). صفحة العرض التجريبية: `?p=demo`

## خطوات التشغيل

### 1) إنشاء الخادم (مرة واحدة)
1. أنشئ Google Sheet جديدًا فارغًا (اسمه أي شيء).
2. من القائمة: **Extensions ← Apps Script**.
3. احذف المحتوى والصق محتوى `Code.gs`، ثم احفظ.
4. شغّل الدالة **`setup`** (وافق على الصلاحيات). تُنشئ الأوراق `Pages` و`Cards` و`Log`، وتولّد **رمز دخول من 6 أرقام**، وتحفظ بريدك لإشعارات التعديلات.
5. افتح **Execution log** وانسخ الرمز. لتغييره: عدّل `NEW_PIN` داخل `setAdminPin` وشغّلها.
6. **Deploy ← New deployment ← Web app**: *Execute as: Me*، *Who has access: Anyone*. انسخ رابط الـ`/exec`.

### 2) ربط الواجهة
ضع الرابط في `config.js`:
```js
API_URL: 'https://script.google.com/macros/s/XXXX/exec',
```

### 3) تفعيل GitHub Pages
في الريبو: **Settings ← Pages ← Deploy from a branch ← main / root**.

بعدها: لوحة الإدارة على `.../admin.html`.

## الاستخدام
1. ادخل لوحة الإدارة برمز الدخول.
2. **صفحة جديدة**: العنوان، الجهة المستفيدة (مثل «للموارد البشرية»)، اللون، عدد البطاقات.
3. لكل بطاقة: اسم المنصة، الهدف، رابط صفحة تسجيل الدخول، أيقونة أو شعار.
4. **حفظ**، ثم انسخ الرابط الموحد (أو استخدم QR) وأرسله للمستفيد.
5. اختياريًا، لكل بطاقة **روابط إضافية** (حتى 6) لكل منها اسم، مثل صفحات Google Sheets. تفتح في تبويب جديد.

## تعديل صاحب الصفحة
- من قسم **صاحب الصفحة** في المحرر: **إصدار رمز تعديل**. يظهر رابط التعديل (`.../admin.html?edit=hr`) ورمز من 8 أرقام **مرة واحدة**، فأرسلهما لصاحب الصفحة.
- صاحب الصفحة يعدّل صفحته فقط: البيانات والبطاقات والروابط. لا يرى صفحات أخرى، ولا يغيّر الرابط المختصر، ولا يحذف الصفحة.
- تعديله يظهر للمستفيدين فورًا، ويصلك بريد بملخص التغييرات.
- **سجل التعديلات** في اللوحة يعرض كل تعديل (من الإدارة أو صاحب الصفحة)، وفيه زر لاسترجاع الصفحة كما كانت قبل أي تعديل. الاسترجاع يحمّل النسخة في المحرر فقط، ولا يُحفظ حتى تضغط حفظ. الشعارات لا تُحفظ في السجل لحجمها.
- **إيقاف الرمز** يمنع صاحب الصفحة فورًا، و**إصدار رمز جديد** يلغي القديم.

## ملاحظات أمنية
- رابط الصفحة عام لمن يملكه؛ الأنظمة نفسها محمية بتسجيل دخولها. الروابط داخل البطاقات تظهر لمن يفحص الصفحة تقنيًا.
- الرمز يُحفظ في Script Properties، وبعد 5 محاولات خاطئة يُقفل الدخول 10 دقائق.
- رموز أصحاب الصفحات تُحفظ مشفّرة (SHA-256 مع ملح)، ولكل صفحة قفل مستقل بعد 5 محاولات خاطئة.
- لا تشارك رابط الـ Sheet ولا رمز الدخول. الصفحات محجوبة عن محركات البحث (`noindex`).
- بعد تعديل `Code.gs` أعد النشر: **Deploy ← Manage deployments ← Edit ← New version**. وإذا احتاج الكود صلاحية جديدة (مثل البريد) شغّل `setup` مرة ووافق عليها قبل النشر.

## الدخول الموحد (SSO)
الموظف يضغط **دخول الموظفين** في أي صفحة، ويدخل ببريده وكلمة مرور البوابة مرة واحدة. بعدها تظهر شارة **دخول مباشر** على بطاقات المنصات المربوطة بحسابه، وتفتح المنصة وهو داخل عليها بدون كلمة مرور. البطاقات الأخرى، ومن لم يسجل دخوله، تعمل كما كانت تمامًا، والدخول العادي في كل منصة باقٍ.

### التجهيز (مرة واحدة)
1. الصق `Code.gs` الجديد في Apps Script واحفظ، ثم أعد تحميل الشيت: تظهر قائمة **الدخول الموحد**.
2. **الدخول الموحد ← تجهيز الجداول**: تُنشأ الأوراق `Employees` و`SsoApps` و`SsoLinks` و`SsoLog`.
3. انشر نسخة جديدة: **Deploy ← Manage deployments ← Edit ← New version** (نفس الرابط، لا تغيير في `config.js`).

### إضافة منصة
1. في `SsoApps` أضف صفًا: `app_id` (مثل `patient-experience`)، `name`، `url` (الرابط الذي تفتح عليه المنصة، ويجب أن يطابق بداية رابط البطاقة)، `active` = `yes`.
2. اختر خلية في الصف ثم **الدخول الموحد ← مفتاح جديد للمنصة المحددة**. انسخ المفتاح (يظهر مرة واحدة) وضعه في إعدادات المنصة باسم `SSO_SECRET`.
3. المفتاح يُحفظ في Script Properties فقط، ولكل منصة مفتاحها. إصدار مفتاح جديد يوقف القديم فورًا.

### إضافة موظف
1. في `Employees` اكتب `email` و`name` و`active` = `yes`.
2. اختر خلية في صفه ثم **الدخول الموحد ← كلمة مرور مؤقتة للموظف المحدد**، وأرسلها له. يُطلب منه تغييرها عند أول دخول.
3. في `SsoLinks` أضف صفًا لكل منصة: `email`، `app_id`، `login` (اسم دخوله أو بريده **في تلك المنصة**؛ يختلف من منصة لأخرى).
4. لإيقاف موظف: `active` = `no` (تتوقف جلسته فورًا). لإلغاء ربطه بمنصة: احذف صفه من `SsoLinks`.

### الأمان
- كلمات مرور البوابة تُحفظ مشفّرة (ملح + HMAC-SHA256 مكرر)، وبعد 5 محاولات خاطئة يُقفل الحساب 10 دقائق.
- التذكرة موقّعة بمفتاح المنصة، صالحة 60 ثانية، ولاستخدام واحد، وتُرسل في `#` الرابط فلا تصل لسجلات الخوادم. المنصة تتحقق منها ثم تمسحها من شريط العنوان.
- كل دخول موحد يُسجَّل في `SsoLog` وفي سجل المنصة.
